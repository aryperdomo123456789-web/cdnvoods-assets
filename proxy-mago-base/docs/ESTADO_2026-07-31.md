# Estado real do projeto — 31/07/2026

Auditoria executada contra o código de `main` e contra a produção
(`voods.suafontee.com` / VPS `45.140.192.237`), com a origem XUI real.
Credenciais de teste aparecem sempre mascaradas (`4Jkn***`, `P2on***`, `Mago***`).

## 1. Resumo executivo

O painel está no ar e a lógica de mascaramento está **correta e comprovada em
laboratório**: a playlist real de 92 MB sai 100% reescrita, sem `dafonte.uk`,
sem `38.190.176.170` e sem credenciais da origem. Porém **o proxy em produção
está devolvendo 403 para todo mundo** e o rewriter consome ~349 MB de RAM por
playlist. Logo: painel funcionando ≠ proxy funcionando.

## 2. Arquitetura atual real

- Uma origem XUI única em SQLite (`XuiOrigin`, chave `settings.xui_origin_id`).
- N domínios públicos (`aliases`) apontando todos para essa origem.
- `public/proxy.php` é a entrada: `AccessGuard` → `StreamProxy` → `PlaylistRewriter`.
- Textual (`get.php`, `player_api.php`, `xmltv.php`, `panel_api.php`, `.m3u8`,
  `.xml`, `.json`) é bufferizado e reescrito; binário (`.ts`) vai em streaming
  chunkado. Redirects nunca são seguidos automaticamente (allowlist de host).
- Coerente com o objetivo: DNS only, VPS pública, XUI escondido.

## 3. Documentação

Cobre bem fluxo de proxy, Cloudflare, deploy e arquitetura leve. Falta:
runbook de troubleshooting (403/404 do guard), nota sobre TLS por domínio de
cliente e nota sobre limites de memória do PHP-FPM.

## 4. O que já funciona (comprovado)

- Origem real responde: `get.php ... output=mpegts` → 200, 92.125.159 bytes.
- Rewriter sobre esse corpo real: 349.833 linhas de mídia, **todas** trocadas
  para `voods.suafontee.com`; `dafonte` = 0 ocorrências, IP da origem = 0.
- `player_api.php` reescrito e continua JSON válido; `server_info.url` sai como
  o domínio público.
- Guard reconhece o alias: Host desconhecido → 404, `voods.suafontee.com` → passa.
- Mascaramento de credenciais no `access_log`.

## 5. O que está parcial

- **Memória**: rewrite da playlist real usa 349 MB de pico e ~525 ms de CPU.
  Com `memory_limit` padrão (128 MB) o processo **morre** (`Allowed memory size
  exhausted`). Com 3–4 downloads simultâneos a VPS cai.
- **Direct source / terceiros**: nenhum link de *stream* sai fora da origem
  (bom), mas 220 `tvg-logo` apontam para hosts de terceiros
  (`fenix7***`, `barserven***`, `fiqueemcasa***`, `slackewn***`). Não vaza o
  main, mas vaza infraestrutura relacionada.
- **Porta no player_api**: `port: 80 / https_port: 443` vêm da origem sem
  ajuste ao esquema público.

## 6. O que não funciona / falta

- **BLOQUEADOR: tudo responde 403 `Denied` em produção.** Ordem do guard
  (404 host desconhecido → 403 UA → 429 → 401 token) prova que a barreira é o
  filtro de User-Agent: `settings.allowed_user_agent` está preenchido no SQLite
  da VPS. Testado com VLC, Lavf, IPTVSmarters, TiviMate — todos 403.
- **TLS**: `https://voods.suafontee.com` não tem certificado válido
  (erro 60 no curl) e o Nginx força 301 de :80 para :443. Player em HTTP entra
  em redirect para um HTTPS quebrado.
- **Painel exposto nos domínios de cliente**: `/`, `/health.php` respondem 302
  para login em `voods.suafontee.com`. O domínio público deveria servir só proxy.

## 8. Riscos de vazamento

- Nenhum vazamento de `dafonte.uk`, IP da origem ou credenciais da origem
  detectado no caminho de código atual. **Baixo risco.**
- Hosts de terceiros em `tvg-logo` — **médio/baixo**.
- Se o rewriter estourar memória, o PHP pode devolver corpo parcial já
  reescrito (não vaza a origem, mas quebra a playlist) — **médio operacional**.

## 9. Veredito

**Ainda não pronto para uso real.** A proteção está correta no código, mas o
proxy em produção nega 100% das requisições (filtro de User-Agent ativo), o
HTTPS do domínio de cliente está quebrado e o consumo de memória por playlist
inviabiliza multiusuário na VPS.

## 10. Próximos passos (ordem)

1. Limpar `allowed_user_agent` no painel (Avançado) ou no SQLite da VPS.
2. Emitir certificado para os domínios de cliente ou aceitar HTTP puro sem 301.
3. Trocar o rewrite bufferizado por reescrita em streaming linha a linha
   (memória constante) e subir `memory_limit` como rede de segurança.
4. Restringir painel/`health.php`/`setup.php` ao domínio do painel.
5. Opcional: proxiar também os `tvg-logo` de terceiros.
